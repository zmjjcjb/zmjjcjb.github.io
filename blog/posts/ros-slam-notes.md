> 项目时间 2024.10 – 2025.02，我负责整套系统。目标是让一台小车在室内环境里自主建图、规划、移动。这篇是当时调参笔记的整理版。

## 系统结构

整个系统拆成四个 ROS 节点包，各司其职：

```text
sensor_driver  →  slam     →  path_planner  →  motion_ctrl
 (雷达/里程计/IMU)  (建图定位)     (A*)             (PID 跟踪)
```

环境是 Ubuntu 22.04 + ROS Noetic，通信全走 topic，节点之间互不掺和——后来改任何一个模块都不用动别处，体会到了解耦的好处。

## SLAM 选型：Gmapping 还是 Cartographer

两个都用过，体感区别：

| | Gmapping | Cartographer |
|---|---|---|
| 依赖 | 必须有里程计 | 可纯雷达（推荐配 IMU） |
| 资源占用 | 低 | 偏高 |
| 地图质量 | 小场景够用 | 大场景更稳，回环强 |
| 上手难度 | 十分钟出图 | 参数多，得啃 |

室内小场景最后用的 **Gmapping** 出图、Cartographer 做对比验证。关键参数就三个：`delta`（分辨率 0.05m）、`particles`（粒子数 80）、`xmax/ymax`（地图边界别开太大）。

## 定位误差从 20cm 到 5cm

一开始定位误差在 20cm 上下晃，排查下来是三个问题叠加：

1. **轮速里程计打滑**：地面光滑，轮子数据不可信。解决：里程计权重降下来，让雷达数据主导
2. **IMU 没标定**：零偏没去掉，yaw 角漂。解决：静止采集 10 分钟算零偏，写进配置
3. **雷达安装震动**：跑起来雷达支架微震，点云抖。解决：加橡胶垫 + 结构加固

```yaml
# amcl 关键调参
amcl:
  odom_model_type: "diff-corrected"   # 差速模型修正版
  laser_z_hit: 0.8                    # 提高雷达观测权重
  odom_alpha1: 0.15                   # 降低里程计信任度（打滑补偿）
  min_particles: 300
  max_particles: 1500
```

三件事做完，静态定位误差压到了 **5cm 以内**。

## A* 规划与动态避障

A* 在栅格地图上搜路径，重点处理两件事：

- **动态障碍**：局部代价地图实时更新，路径重规划响应时间压在 **0.3 秒**内
- **路径平滑**：A* 出来的路径是锯齿状的，过一遍梯度平滑再交给控制器

## PID 轨迹跟踪

跟踪控制器是纯 PID，但不是拿 PID 去追"路径点"，而是**追路径上的投影点**（纯跟踪思想 + PID 修正角速度），这样急弯不会画龙。

最终直线跟踪误差 **≤ 10cm**，弯道略大但可接受。

## 多传感器融合

最后把激光雷达 + 轮速里程计 + IMU 用扩展卡尔曼滤波（robot_localization 包）融了一下：

- 雷达管全局定位（不长漂）
- IMU 管短时姿态（高频、平滑）
- 里程计管速度平滑

融合之后最直观的变化：黑暗环境里雷达退化时，车不再"失明"，靠 IMU + 里程计也能平稳滑行一段。

## 复盘

这个项目最大的收获不是 5cm 这个数字，而是**理解了"定位是概率问题"**：粒子云的形状比单点坐标更值得看。后来做无人船感知时，这套多传感器融合的思路直接复用了。

工具链备忘：Gmapping/Cartographer 建图、AMCL 定位、move_base 规划、robot_localization 融合，全都是 ROS 生态现成轮子——先会用轮子，再造轮子。
